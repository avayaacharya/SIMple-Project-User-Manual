Core Components — Responsibilities
File Role Key Exports / Logic Type
App.tsx Application root Reads sessionStorage on load; renders <LoginPage> or <Portal> based on auth state. Entry
LoginPage.tsx Authentication screen Validates Employee ID + password against USERS in types.ts; writes JSON to sessionStorage['csm-auth']. Component
Portal.tsx Main shell Renders navbar (with NOS-i logo), left tree panel, and content area. Handles module switching and logout. Component
TreeNav.tsx Navigation tree Receives the module's tree[] array and renders a collapsible multi-level navigation. Highlights the active section. Component
ContentPanel.tsx Content renderer Injects section HTML via dangerouslySetInnerHTML. Runs upgradeFigures() to auto-swap any legacy figure-placeholder divs with real <figure> elements. Includes a Print button. Component
data/types.ts Types + credentials Exports USERS map, and interfaces: User, Module, Section, TreeNode. Data
data/hr-content.ts HR module data Exports hrModule with the full navigation tree and HTML content for all 14 HR sections (Figuras 1-1 → 2-19). Data
data/contracts-content.ts Contracts module data Exports contractsModule with navigation tree and HTML content for all Contracts sections. Data
index.css Design system Full CSM Blue design system: CSS custom properties, typography, .doc-figure, .figure-placeholder, .inline-icon, .note-box, .step-badge, print styles. Styles

Data Layer — types.ts Structure
InterfaceFieldsUsed By
User name: string · modules: string[] Portal.tsx — displays name in navbar; filters which modules are shown
Module id · title · icon · sections · tree Portal.tsx — module tab list; TreeNav.tsx — navigation; ContentPanel.tsx — section lookup
Section title: string · content: string (HTML) · parent?: string ContentPanel.tsx — renders the HTML; TreeNav.tsx — displays the title

USERS (constant) Record<empId, { password, name, modules[] }> LoginPage.tsx — credential validation (no hashing — demo only)
🔐
Authentication Flow
1

User enters Employee ID (e.g. EMP001) and password on the Login screen.

2

LoginPage.tsx looks up the ID in USERS (from types.ts) and compares the password directly.

3

On success, a JSON object { id, name, modules } is written to sessionStorage under key csm-auth.

4

App.tsx reads csm-auth on mount — if it exists, <Portal> renders; otherwise <LoginPage>.

5

Portal.tsx uses auth.modules[] to show only the module tabs the employee has access to.

6

On logout, sessionStorage.removeItem('csm-auth') is called and the app resets to the login screen.

Note: sessionStorage is cleared automatically by the browser when the tab is closed — no explicit logout is required.
